## 导读

本文是第 5 周「多智能体系统」的核心论文,回答一个此前几乎无人系统研究过的问题:多智能体 LLM 系统(Multi-Agent LLM Systems, MAS)到底为什么失败?课程前面几周讲的都是"怎么把单个 Agent 做强"(ReAct、SWE-agent、记忆系统等),而工业界和开源社区却在大量堆叠多智能体框架(ChatDev、MetaGPT、AutoGen 等)。本文作者实测 7 个主流开源 MAS,发现失败率高达 41%–86.7%,于是自下而上地构建了第一个实证驱动的失败分类法 MAST(Multi-Agent System Failure Taxonomy):14 种失败模式、3 大类别(系统设计问题、智能体间失调、任务验证),并用 1642 条标注轨迹的 MAST-Data 数据集量化了各模式的分布。

对课程而言,本文的价值有三:其一,它给了我们一套诊断多智能体系统的"词汇表",后面读 AutoGen、DyLAN 时可以对照检视它们各自解决了哪类失败;其二,它示范了 LLM-as-a-Judge 在大规模标注中的校准方法(o1 标注器与人类一致率 κ=0.77);其三,它最重要的结论是反直觉的——多数失败源于系统设计而非底层模型能力,简单修提示词只能带来有限提升(最高 +15.6%),可靠 MAS 需要结构性重设计。

## 论文精读

### 摘要

尽管业界对多智能体 LLM 系统(MAS)热情高涨,它们在流行基准上的性能提升往往微乎其微。这一差距凸显了对"MAS 为什么失败"进行有原则理解的迫切需求。回答这个问题需要系统性地识别与分析失败模式。作者提出 MAST-Data:一个包含 1600 余条标注轨迹的综合数据集,采集自 7 个流行 MAS 框架。MAST-Data 是第一个勾勒 MAS 失败动态的多智能体系统数据集,可用于指导未来更好的系统开发。为了对 MAST-Data 进行系统化失败分类,作者构建了第一个多智能体系统失败分类法 MAST(Multi-Agent System Failure Taxonomy)。MAST 建立在对 150 条轨迹的严格分析之上,全程由专家人工标注者指导,并通过高标注者间一致性(κ = 0.88)验证。该过程识别出 14 种独特的失败模式,聚为 3 大类:(i) 系统设计问题;(ii) 智能体间失调(inter-agent misalignment);(iii) 任务验证。为实现可扩展标注,作者开发了一个与人类标注高度一致的 LLM-as-a-Judge 管线。借助 MAST 与 MAST-Data,作者分析了不同模型(GPT-4、Claude 3、Qwen2.5、CodeLlama)与任务(编码、数学、通用智能体)上的失败模式,展示了通过更好的 MAS 设计获得的改进空间。分析揭示:已识别的失败需要更复杂的解决方案,为未来研究勾勒出清晰的路线图。论文公开了 MAST-Data、MAST 与 LLM 标注器。

论文开篇引用托尔斯泰《安娜·卡列尼娜》"幸福的家庭都是相似的,而不幸的家庭各有各的不幸",并戏仿为"成功的系统都相似,而失败的系统各有各的问题"——这正点出了本文的动机:失败不是单因,需要一套细粒度分类法。

### 1 引言:多智能体系统的 Adoption 与失败现实

作者首先给出形式定义:LLM 智能体是具备提示规范(初始状态)、对话轨迹(状态)与环境交互能力(动作,如工具使用)的人工实体;MAS 则是通过编排(orchestration)实现集体智能的智能体集合,可支撑任务分解、性能并行化、上下文隔离、专业化模型集成与多样性推理讨论。

然而实证分析揭示:7 个 SOTA 开源 MAS 的失败率在 41% 到 86.7% 之间,而且社区对"如何构建可靠 MAS"并无共识。由此引出核心问题:为什么 MAS 会失败?

为此作者构建了 MAST-Data:1642 条标注执行轨迹(失败定义为 MAS 未达成任务目标),采集自 7 个流行 MAS 框架,使用 GPT-4 系列与 Claude 系列两大模型家族,覆盖编码、数学求解、通用智能体任务;同时发布 MAST-Data-human(21 条轨迹、每条由三位人类专家标注)。构建该数据集有两大挑战:MAS 失败的根因难以验证、缺乏标准化的失败定义——这正是先构建 MAST 分类法的原因。MAST 由 6 位专家对 150 余条轨迹(平均每条超过 15,000 行文本)做扎根理论分析得出;三位标注者独立迭代标注 15 条轨迹直至 κ = 0.88。为规模化标注,又开发了基于 OpenAI o1 的 LLM 标注器,与人类专家校准到 κ = 0.77,并在两个全新未见 MAS 与基准上验证了泛化性(κ = 0.79)。

论文的四项贡献:(1) 开源首个大规模 MAS 失败数据集 MAST-Data(7 个 MAS、4 个模型家族);(2) 提出首个实证落地的失败分类法 MAST;(3) 开发与 MAST 集成、可扩展的 LLM-as-a-Judge 标注管线;(4) 通过案例研究证明:MAST 识别的失败多源于系统设计问题,而非仅仅 LLM 能力限制或提示词遵循问题,需要超越表层修补的结构性重设计。

### 2 相关工作

- **智能体系统的挑战**:Agent Workflow Memory 解决长程网页导航、DSPy 处理智能体流程编程、StateFlow 关注状态控制;已有综述概括了 MAS 的挑战与风险,但都没有给出细粒度、实证落地的"为什么失败"分类法。各类基准提供自上而下的聚合性能视角,本文则补充自下而上的具体失败模式分析。
- **智能体系统设计原则**:Anthropic 的《Building Effective Agents》博客强调模块化组件、避免过度复杂框架;Kapoor et al.(AI Agents That Matter)指出复杂性阻碍实用。本文将这些洞见扩展到多智能体场景。
- **相关数据集与分类法**:Bansal et al. 归纳人机交互挑战;多轮对话/代码生成错误分类法与本目标不同;AgentEval、AGDebugger、Who&When 数据集等并行工作关注归因于特定智能体与步骤。MAST-Data 与 MAST 是首个聚焦 MAS 失败模式的实证数据集与分类法。

### 3 MAST-Data 数据集:方法论

构建 MAS 失败数据集有两个独特困难:其一,传统软件的失败常有明确根因,而 MAS 失败涉及复杂的智能体交互、模型行为与系统设计的复合效应;其二,缺乏标准化失败框架导致跨系统标注不一致。作者的方法论围绕"先建分类法、再建标注管线"展开。

#### 3.1 扎根理论驱动的数据收集

为发现多样且可泛化的失败模式,作者先从 5 个 MAS 框架(HyperAgent、AppWorld、AG2、ChatDev、MetaGPT)收集 150 条轨迹,由 6 位人类专家细察。为避免预设立场,采用质性研究方法扎根理论(Grounded Theory, GT),让失败模式从数据中自然涌现。具体使用理论抽样(theoretical sampling)选取覆盖不同系统目标与交互模式的框架;再迭代运用开放编码(open coding)标记失败行为、持续比较分析(constant comparative analysis)提炼模式、备忘(memoing)记录洞见、理论化(theorizing)结构化失败模式定义,直至理论饱和(theoretical saturation)。这一过程人力成本极高:每位专家在这 150 条轨迹上投入超过 20 小时。

#### 3.2 用标注者间一致性(IAA)标准化失败标签

为让 GT 分析得到的观察变成可跨系统一致使用的标签,作者通过标注者间一致性(Inter-Annotator Agreement, IAA)研究迭代验证并精炼 MAST:每轮由三位专家独立标注 5 条随机轨迹,随后集体讨论消解分歧,据此调整失败模式定义、增删或合并模式。三轮 IAA 共耗时约 10 小时(不含标注本身),最终平均 Cohen's Kappa 达 κ = 0.88,证明 MAST 提供了清晰且共享的失败理解。图 3 给出一个轨迹示例:AppWorld 中 Phone Agent 未向 Supervisor 说明"用户名应为手机号"这一 API 要求(FM-2.4 信息隐瞒),Supervisor 也未追问,导致反复登录失败、任务失败——这正是细粒度标注的价值。

#### 3.3 LLM-as-a-Judge 标注管线

人工标注 1600+ 条轨迹成本过高,作者基于已验证的 MAST 构建 LLM 标注器:向 LLM(OpenAI o1)输入执行轨迹、MAST 定义与来自人类标注数据的少样本示例,令其分类观察到的失败模式。在留出集上验证:o1 零样本准确率 89%、F1 0.64、κ 0.58;o1 少样本(few-shot)准确率 94%、召回 0.77、精确率 0.833、F1 0.80、Cohen's κ 0.77——据此采用少样本版本规模化标注。

#### 3.4 数据集构成与泛化性验证

大规模收集前,作者先在两个新 MAS(OpenManus、Magentic-One)与两个新基准(MMLU、GAIA,后者代表全新的通用智能体任务域)上做out-of-domain验证:人类 IAA 达 κ = 0.79,证明 MAST 无需修改即可迁移。最终 MAST-Data 覆盖 7 个框架:ChatDev、MetaGPT、HyperAgent、AppWorld、AG2(MathChat)、Magentic-One、OpenManus,包含人类评测任务完成率(HE)、人类标注(HA)、LLM 标注(LA)三种配置,共 1642 条轨迹。作者还尝试纳入闭源平台 Manus:它在 ProgramDev 上取得 60% 成功率,但因不公开底层模型、不提供完整执行轨迹,无法做细粒度失败标注,故未收录。

### 4 MAST:多智能体系统失败分类法

MAST 识别 14 种细粒度失败模式,映射到智能体间对话的三个阶段(执行前、执行中、执行后),归为 3 大类别。在全部 1642 条轨迹上,三类失败占比为:系统设计问题 44.2%、智能体间失调 32.3%、任务验证 23.5%。作者明确说明:部分失败可归因于 LLM 的固有限制(如幻觉、指令遵循),但 MAST 聚焦于可通过系统设计、智能体协调与验证改进的问题空间。各模式在 1642 条轨迹中的发生率:FM-1.1 不服从任务规范 11.8%、FM-1.2 不服从角色规范 1.5%、FM-1.3 步骤重复 15.7%(所有模式中最高)、FM-1.4 丢失对话历史 2.8%、FM-1.5 不知终止条件 12.4%、FM-2.1 会话重置 2.2%、FM-2.2 未请求澄清 6.8%、FM-2.3 任务偏航 7.4%、FM-2.4 信息隐瞒 0.85%、FM-2.5 忽视其他智能体输入 1.9%、FM-2.6 推理-行动失配 13.2%、FM-3.1 过早终止 6.2%、FM-3.2 无或不完整验证 8.2%、FM-3.3 错误验证 9.1%。

#### FC1 系统设计问题:失败源于设计决策与糟糕的提示规范

包含 FM-1.1 至 FM-1.5。**洞见 1:MAS 失败不仅是底层模型能力的函数;使用同一模型,设计良好的 MAS 也能带来性能增益。** FC1 失败发生在执行期,但根因常在执行前的架构、提示与状态管理决策。作者强调,FM-1.1/1.2 表面像指令遵循问题,实则有三层更深原因:(1) MAS 在智能体角色与工作流上的设计缺陷;(2) 用户提示规范差;(3) 底层 LLM 限制。一个典型案例:要求 ChatDev 做"每天随机选词的 Wordle 游戏",即便用户显式写明"不要固定词库",系统仍生成固定字典——问题出在 MAS 解析规范的设计。干预实验显示:仅改进智能体角色规范(同一用户提示、同一 GPT-4o),ChatDev 成功率提升 +9.4%。

#### FC2 智能体间失调:关键信息流在交互协调中断裂

包含 FM-2.1 至 FM-2.6,涵盖协调失败。**洞见 2:聚焦上下文或通信协议的方案对 FC2 往往不够,这类失败要求智能体具备更深层的"社会推理"(social reasoning)能力。** 作者指出:MCP、A2A 等标准化消息格式的创新,解决的是异构工具/智能体提供商间的通信;但 FC2 错误即便在同一框架内以自然语言通信时也照样发生——这是"心智理论"(theory of mind)的坍塌,即智能体无法准确建模其他智能体的信息需求。基础 LLM 的预训练并不针对这种细粒度智能体间动态,因此稳健解法需要 MAS 架构改进与模型级"通信智能"的结合。此外,FC2 的诊断很复杂:相似的表层行为(如信息缺失)可能源于隐瞒(2.4)、忽视输入(2.5)或上下文管理不当(1.4),这正是 MAST 细粒度模式的必要性。

#### FC3 任务验证:验证过程不足以检测或纠正错误

包含 FM-3.1 过早终止、FM-3.2 无或不完整验证、FM-3.3 错误验证。**洞见 3:需要多级验证(multi-level verification)。当前验证器的实现普遍不足,仅依赖最终阶段的低层检查是不够的。** 配备显式验证器的 MetaGPT 与 ChatDev 总失败确实更少,但验证器不是银弹:ChatDev 生成的国际象棋程序通过了"代码可编译"这类表层检查,却因未对照实际游戏规则验证而带运行时缺陷,输出不可用。GT 分析发现,许多现有验证器即便被提示做彻底验证,也只做表层检查(如是否编译、有无遗留 TODO)。作者主张向传统软件开发学习"提交前先测试":利用外部知识、在生成过程中持续收集测试输出、对低层正确性与高层目标做多层次检查。干预实验:给 ChatDev 增加一个高层任务目标验证步骤,ProgramDev 任务成功率提升 +15.6%。

### 5 迈向更好的多智能体 LLM 系统

#### 5.1 MAST-Data 中的失败分布

失败分布随 MAS 架构特征差异显著:AppWorld 因星型拓扑、无预定义工作流,终止条件不明显,频发过早终止(FM-3.1);OpenManus 倾向步骤重复(FM-1.3);HyperAgent 的主导失败是步骤重复与错误验证(FM-3.3)。这说明不存在万能解法。模型层面:在 MetaGPT 编程任务上比较 GPT-4o 与 Claude 3.7 Sonnet,GPT-4o 总体更优,其 FC1(系统设计问题)失败显著少 39%,表明其指令遵循与智能体协作的"社会推理"更强;但两者的 FC3(验证)失败都很多,说明验证挑战与所用 LLM 无关。架构层面:同样用 GPT-4o 跑 ProgramDev-v2,MetaGPT 的 FC1 与 FC2 失败比 ChatDev 少 60–68%,但 FC3 失败反而是 ChatDev 的 1.56 倍——MetaGPT 靠 SOP(标准作业程序)保证规范遵循,而 ChatDev 的架构在设计上就更重视测试与评审阶段。结论:LLM 选择与 MAS 架构共同塑造失败图景,改进需要两者兼顾。

#### 5.2 MAST 作为实用开发工具

聚合成功率会掩盖具体优化的效果。MAST 提供结构化词汇做系统性失败拆解,配合 LLM 标注器即可对特定系统输出量化的失败画像;干预前后对比失败模式分布,可以看出哪些模式被缓解、有何权衡——这解释了"干预为什么有效",是聚合指标之外的关键调试工具。作者还将 MAST 封装为 Python 库,`pip install agentdash` 即可对任意 MAS 轨迹自动标注失败模式。

#### 5.3 超越模型能力:系统设计的首要性

如果把失败简单归咎于 LLM 幻觉,就忽略了组织层面的规律。作者援引组织理论:即使由精明个体构成的组织,若组织结构有缺陷也会灾难性失败(Perrow 的《Normal Accidents》);高可靠性组织(high-reliability organizations)研究表明,良定义的设计原则可以预防此类失败。本文干预实验中,在底层模型不变的前提下,仅靠系统工作流与提示改动就取得最高 15.6% 的提升,证明失败可通过更好的系统设计解决。但首轮干预并未消除所有失败模式,任务完成率仍低——高可靠性可能需要从智能体组织到模型级的组合式变革。

### 6 结论

本文是对"MAS 为什么失败"的首次系统调查,产出:MAST-Data(7 个流行 MAS 框架、超过 1600 条标注执行轨迹的公开资源);MAST(经扎根理论构建、κ = 0.88 验证、14 种失败模式 × 3 大类别的首个实证失败分类法);以及与人类专家高度一致的 LLM 标注器。作者对 MAS 的潜力感到兴奋,但其广泛落地取决于可靠性——MAST-Data 提供失败动态的经验基础,MAST 提供诊断与缓解失败的标准化语言,共同为社区开辟具体的研究方向。

**干预案例研究**(表 5):案例一 AG2-MathChat(GSM-Plus 随机 200 题,每组重复 6 次):GPT-4 下 baseline 84.75±1.94,改进提示(增加验证环节)后 89.75±1.44,新拓扑(Problem Solver / Coder / Verifier 三角色、仅 Verifier 可终止)85.50±1.18(威尔科克森检验 p=0.4,不显著);GPT-4o 下 84.25±1.86 → 89.00±1.38 与 88.83±1.51(p=0.03,显著)。案例二 ChatDev:细化角色提示(强化层级与角色遵循,如只有上级智能体可终结对话)与拓扑改造(DAG 改为带最大迭代截断的循环图、CTO 确认所有评审满足后终止)后,ProgramDev-v0(32 个任务)从 25.0% 提升至 34.4% 与 40.6%,HumanEval 从 89.6% 提升至 90.3% 与 91.5%。两案例均显示:拓扑级改动比提示级改动更有效,但提升幅度有限,验证了"战术性修补不够"的判断。

**战术方法与结构策略**(表 4):战术方法(tactical approaches)包括清晰的角色/任务定义、交叉验证、会话模式设计、自我验证、多智能体验证等;结构策略(structural strategies)包括全面验证与单元测试生成、标准化通信协议、概率化置信度度量、记忆与状态管理等。作者将各类策略与三大失败类别一一映射,构成未来研究的路线图。

## 要点速览

- 7 个 SOTA 开源 MAS 的任务失败率在 41%–86.7% 之间,多智能体并未自动带来收益。
- MAST 是首个实证落地的 MAS 失败分类法:14 种失败模式,归为系统设计问题(FC1, 44.2%)、智能体间失调(FC2, 32.3%)、任务验证(FC3, 23.5%)三大类。
- 发生率最高的失败模式是步骤重复(FM-1.3, 15.7%),其次是推理-行动失配(FM-2.6, 13.2%)与不知终止条件(FM-1.5, 12.4%)。
- 方法论采用扎根理论:6 位专家分析 150 条轨迹(每条均超 1.5 万行),人均投入 20+ 小时,迭代三轮 IAA 达 κ = 0.88。
- LLM-as-a-Judge 标注器(o1 少样本)与人类专家一致率:准确率 94%、Cohen's κ 0.77;在未见的 MAS 与基准上泛化验证 κ = 0.79。
- MAST-Data 共 1642 条标注轨迹,覆盖 ChatDev、MetaGPT、HyperAgent、AppWorld、AG2、Magentic-One、OpenManus 与 GPT-4/Claude/Qwen2.5/CodeLlama 四个模型家族。
- 同一模型下仅改进系统设计即可提升成功率:ChatDev 角色规范修复 +9.4%,增加高层目标验证步骤 +15.6%。
- 换模型改变失败结构:MetaGPT 中 GPT-4o 的系统设计类失败比 Claude 3.7 Sonnet 少 39%,但两者的验证类失败都居高不下。
- 换架构同样改变失败结构:MetaGPT 的 FC1/FC2 失败比 ChatDev 少 60–68%,但 FC3(验证)失败反而是其 1.56 倍。
- 核心论断:多数 MAS 失败源于组织与设计层面而非个体模型能力,需要结构性重设计(多级验证、标准化通信协议、置信度量化、记忆管理),而非提示词层面的战术修补。
