## 导读

这是第 5 周「优化」一讲的另一篇核心论文(ICLR 2026 Oral),与同讲的 MIPROv2、Soylu et al. 构成"提示优化 vs 微调"的完整光谱。GEPA(Genetic-Pareto)回答一个尖锐的问题:**优化一个由 LLM 模块组成的系统,一定要动权重(RL/微调)吗?** 作者注意到:RL(如 GRPO)靠稀疏标量奖励估计策略梯度,动辄需要数万 rollout;而任何 LLM 系统的执行轨迹(推理链、工具调用、编译器报错)本身就是**自然语言**,对 LLM 来说是远比标量丰富的学习介质。GEPA 因此让"反思 LLM"阅读执行轨迹与评估轨迹,诊断问题、改写提示,并以**帕累托前沿**维护多样候选避免局部最优。结果:6 个任务上平均超 GRPO 6%、最多 20%,rollout 少 35 倍;全面超越最强提示优化器 MIPROv2(+10% 以上);提示还更短(最多 9.2 倍)、可跨模型迁移。它是"语言反思 > 标量梯度"这一论点的代表作。

## 论文精读

### 摘要(全译)

LLM 越来越多地通过 GRPO 等强化学习方法适配下游任务,而这通常需要数千个 rollout 才能学会新任务。我们 argue:与从稀疏标量奖励导出的策略梯度相比,语言的**可解释本质**为 LLM 提供了丰富得多的学习介质。为验证这一点,我们提出 GEPA(Genetic-Pareto),一个充分引入**自然语言反思**的提示优化器,从试错中学习高层规则。给定任一包含一个或多个 LLM 提示的 AI 系统,GEPA 采样轨迹(如推理、工具调用与工具输出),用自然语言对其反思,以诊断问题、提出并检验提示更新,并把自身尝试的帕累托前沿上的互补经验结合起来。得益于该设计,GEPA 常能把**哪怕很少的 rollout 转化为大幅质量提升**。在六个任务上,GEPA 平均超出 GRPO 6%、最多 20%,同时 rollout 少 35 倍;超过此前最强的提示优化器 MIPROv2 10% 以上(如 AIME-2025 上 +12% 准确率),并展示了作为代码优化推理时搜索策略的可观前景。代码已开源(github.com/gepa-ai/gepa)。

### 1. 引言

- 复合 AI 系统把模糊的自然语言规范与检索、代码执行等工具结合;如何优化它们?主流是 **RLVR**(可验证奖励的强化学习,如 GRPO),把成功指标当作 rollout 末端的标量奖励来估计策略梯度。有效但**样本效率极低**——近期用 GRPO 的工作动辄数十万 rollout。这在工具调用昂贵、推理预算有限、或根本无法微调最强闭源模型权重时成为瓶颈。
- **关键观察**:任何 LLM 系统的 rollout 都可以序列化为自然语言轨迹——模块指令、推理链、工具调用、乃至奖励函数的内部过程(如编译器报错在被压缩成标量之前的原文)。LLM 天然读得懂这些,因此**用自然语言在轨迹上"刻意学习"的算法,能比标准 RL 更好地利用 LLM 的语言先验**。
- GEPA = 文本反思 + 多目标进化搜索:迭代地用新 rollout 的自然语言反馈"变异"提示;为避免贪心提示优化陷入局部最优,维护**帕累托前沿**——不只进化全局最优提示,而是对每个题目实例的最优提示做随机探索。
- 评测:HotpotQA(多跳推理)、AIME/LiveBench-Math(数学)、IFBench(指令遵循)、PUPA(隐私感知委托)、HoVer(检索增强验证),模型用 Qwen3 8B(开源)与 GPT-4.1 Mini(闭源)。Qwen3 8B 上 GEPA 以最多 35× 少的 rollout 超 GRPO(24k rollouts)最多 20%、平均 +6%;全面超 MIPROv2,聚合提升 +13%,是 MIPROv2(+5.6%)的两倍多。

### 2. 问题陈述

- **复合 AI 系统**形式化为 Φ=(M, C, X, Y):语言模块 M(每个含提示 π、权重 θ、输入输出 schema)、控制流 C、全局输入输出 schema。该定义涵盖 agent、多智能体系统与 ReAct、Archon 等脚手架。
- 可学习参数是 ⟨Π, Θ⟩(所有提示 + 所有权重),优化目标是最大化任务分布上的指标 μ 期望。
- **样本高效优化约束**:rollout(执行 Φ 并评估 μ)在算力/金钱/时间上昂贵,预算至多 B 次。核心挑战:**如何从每次昂贵 rollout 中榨取最大学习信号**。(该设定使 GEPA[只动提示]与 GRPO[动权重]可在同一问题定义下公平对比。)

### 3. GEPA:反思式提示进化

三大原则:遗传式提示进化、自然语言反馈反思、帕累托候选选择。GEPA 只进化提示 Π,权重 Θ 冻结。

**遗传优化循环**:候选池初始只有基系统;每轮 (i) 选出有希望的候选;(ii) 在任务 minibatch 上提出并评估变体;(iii) 若超过父代则加入池中并在验证集 D_pareto 上评估;预算耗尽后返回 D_pareto 上聚合分最高的候选。变体来自两种算子:**反思式变异**(主)与 **System-Aware Merge 交叉**(附录 D.1)。

**反思式提示变异(核心)**:
- 系统执行轨迹暴露各模块行为与职责;与最终成败配对后有很强**诊断价值**。LLM 通过反思做**隐式信用分配**(把成败归因到具体模块),再对目标模块做定点更新——单次更新也常带来大幅提升(图 5:PUPA 任务上从 82.26 → 97.6 的进化轨迹,每步累积一条"隐私改写"高层经验)。
- 流程:选候选 → 在 minibatch 上执行并追踪轨迹 → 提取模块输入/输出/推理 → **反馈函数 μ_f** 返回数值分 + 文本反馈 → 轮询选一个模块 → 反思 LLM 看到(当前提示、轨迹、分数、反馈),把成败归因到提示元素并提出改写 → minibatch 复评,有提升才入库。
- **评估轨迹也是诊断信号**:很多指标在被压缩为标量前会产生丰富文本(编译错误、失败 rubric)。GEPA 把 μ 扩展为 **μ_f** 返回 feedback_text;人类评分者的解释性反馈也可作为辅助反馈注入。

**3.1 帕累托候选选择**:
- 每轮总选全局最优候选会陷入局部最优(图 6a:第一个"新策略"出现后反复精炼失败,耗尽预算)。
- GEPA 用"illumination"式策略:对**每个训练实例**记录所有候选的最高分,构成帕累托前沿;至少在一个实例上最优的候选保留,被严格支配的剪枝;再按"领先实例数"加权随机采样。既逃出局部最优又不膨胀搜索,平衡探索/利用。

### 4. 评测(六大观察)

设置:标准 train/val/test 切分;六个基准各配已有复合系统与反馈函数;对比 MIPROv2、Trace(OptoPrime)、TextGrad、GRPO(LoRA,亦验证全参微调)。

**主结果(Qwen3 8B,表 1)**:GEPA 聚合 54.85(基线 45.23,+9.62),GRPO 48.91(+3.68,24k rollouts),MIPROv2 47.84(+2.61);GEPA 总预算仅 ~3.9k rollouts。IFBench 上 GEPA 用 678 个 rollout 达 38.61%,超过 GRPO 用 24000 rollout 的 35.88%。单项:HotpotQA 62.33 vs GRPO 43.33;HoVer 52.33 vs 38.67;PUPA 91.85 vs 86.66(AIME 上 GRPO 略高)。

**GPT-4.1 Mini(表 2)**:GEPA+Merge 聚合 66.36(+13.33),GEPA 65.22(+12.19),均超 TextGrad(59.14)、MIPROv2(58.67)、Trace(56.30)。

- **观察 1(样本效率)**:GEPA 以 4-35× 少的 rollout 达到最优测试性能;在 6 任务中 5 个超 GRPO(最多 +19%)。与 GRPO 最佳验证分匹配所需 rollout:HotpotQA 243、IFBench 402、HoVer 330、PUPA 1143、AIME 1179、LiveBench-Math 306——**最高 78× 样本效率**。若只算训练集 rollout(验证开销不计),GEPA 到达最优仅需 79-737 次。
- **观察 2(仅优化指令就够了)**:GEPA 在所有设定下超 MIPROv2(最高 +11.1% GPT-4.1 mini / +10.3% Qwen3 8B)。此前研究认为少样本示例优化强于指令优化;GEPA 反转了这一趋势,归功于 LLM 指令遵循与自我反思能力的进步 + GEPA 的设计。反思进化出的指令**泛化差距(generalization gap)也更小**。
- **观察 3(帕累托选择的价值)**:固定进化框架只换候选选择策略:GEPA 帕累托采样聚合 +12.44%,显著超 SelectBestCandidate(TextGrad 式贪心,+6.05)与 BeamSearch(APO 式,+5.11);最多超 11.33%/8.17%。搜索树可视化显示贪心一步后即停滞,帕累托采样长出均衡的树。
- **观察 4(提示更短更省)**:反思进化的指令比 MIPROv2 的(多示例)提示**最多短 9.2 倍**;性能更高的优化器总体产出更短的提示——直接降低 API 输入 token 成本与延迟。
- **观察 5(交叉/Merge)**:System-Aware Merge 把不同谱系各自进化出的最优模块拼成一个候选,最多再 +5%(GPT-4.1 Mini 上聚合再 +2%);但 Qwen3 8B 上超参未调时可能负收益,何时触发 Merge 需自适应,留作未来工作。
- **观察 6(跨模型迁移)**:用弱模型 Qwen3-8B 优化出的提示直接给 GPT-4.1-Mini 用,聚合 **+9.00%**(HotpotQA 最高 +27.67%),竟超过直接在 GPT-4.1-Mini 上优化的 MIPROv2/TextGrad/Trace。

### 5. 扩展应用

- **作为推理时搜索**:把待解任务全集当作"训练集"(D_train = D_pareto = 全部任务),GEPA"过拟合"任务集,把一个任务 rollout 中学到的经验迁移给其他任务。在 NPUEval(AMD XDNA2 NPU 内核)与 KernelBench(NVIDIA V100 CUDA)上做代码生成:**μ_f 动态注入领域知识**——按编译报错检索技术手册相关章节,把架构最佳实践带入提示进化;温度采样用缓存消除后,提升可归因于提示更新本身。GPT-4o 的 Sequential10 精炼 agent 在 NPU 上平均向量利用率仅 4.25%(加 RAG 后改善,论文续表给出 GEPA 的进一步增益)。
- **对抗性提示搜索**(5.2):GEPA 亦可用于搜索越狱提示等对抗用途,展示同一框架的双刃性。

### 结论与意义

- **"语言是比标量奖励更丰富的学习介质"** 是本文的中心论点,证据是样本效率数量级的提升。
- 对工程的启示:在预算受限、无法微调(闭源模型/昂贵工具调用)的场景,反思式提示进化是比 RL 更实用的第一选择;且优化产物(短指令)可跨模型、跨家族迁移。
- 与课程脉络的关系:GEPA 是 MIPROv2(同讲、同作者群)之后的下一代提示优化器,也是 DSPy 生态的最新成果;其"执行轨迹 + 评估轨迹都可用于反思"的思想与 AutoLibra(第 8 周)的元评测一脉相承。

## 要点速览

- GEPA 三要素:反思式提示变异(自然语言反馈)+ 遗传式候选池 + 帕累托前沿采样(防局部最优)。
- 反思 LLM 的输入:(当前提示、系统执行轨迹、分数、文本反馈),输出定点改写;单次反思即可带来大提升。
- **μ_f 反馈函数**:把标量指标 μ 扩展为"分数 + 文本反馈"(编译器报错、失败 rubric、人工解释),是反思的关键原料。
- 样本效率:比 GRPO 少 4-35× rollout;匹配 GRPO 最佳验证分最高省 78×;只用 79-737 个训练 rollout 可达最优。
- 主结果:6 任务平均 +6%(vs GRPO)、全面超 MIPROv2(聚合 +13% vs +5.6%);IFBench 678 rollouts 胜 GRPO 24000 rollouts。
- 帕累托选择消融:+12.44% vs 贪心 +6.05% / 束搜索 +5.11%。
- 提示最多比 MIPROv2 短 9.2×;跨模型迁移:Qwen3-8B 优化 → GPT-4.1-Mini +9%。
- 局限:AIME 等纯数学上 GRPO 仍可更强;Merge 的调度需自适应;作为推理时搜索仅初步验证。
