## 导读

本文是第 4 周「Agent 设计模式」专题的核心论文（importance: must）。ReAct（Reason + Act）是普林斯顿大学 Shunyu Yao 等人在 ICLR 2023 发表的经典工作，也是当今几乎所有 LLM Agent 框架的基石范式：让模型在解决任务时交替产生"思考（Thought）"与"行动（Action）"，用推理指导行动、用行动获取外部信息反哺推理。

在 ReAct 之前，LLM 的推理能力（如思维链 Chain-of-Thought）与行动能力（如动作规划生成）是被分开研究的两个主题。ReAct 首次证明二者可以协同增效：推理轨迹帮助模型分解目标、跟踪进度、处理异常；行动则让模型与 Wikipedia API、模拟环境等外部世界交互，获取额外信息。论文在 HotpotQA、Fever 两个知识密集型任务和 ALFWorld、WebShop 两个交互式决策任务上验证了有效性，并系统分析了 ReAct 与 CoT 各自的成败模式。读懂 ReAct，才能理解后续 Reflexion、AutoGPT、各类工具调用 Agent 的设计源头。

## 论文精读

### 摘要（Abstract）

尽管大语言模型（LLM）在语言理解与交互式决策等任务上表现出色，但其推理能力（如思维链提示 Chain-of-Thought prompting）与行动能力（如动作计划生成）此前主要被作为两个独立课题研究。本文探索用 LLM 以交错（interleaved）方式同时生成推理轨迹（reasoning traces）与任务专属动作（task-specific actions），从而让二者产生更强的协同：推理轨迹帮助模型归纳、跟踪并更新行动计划，以及处理异常情况；而行动则让模型能够对接外部信息源（如知识库或环境）并收集额外信息。作者将这一名为 ReAct 的方法应用于多种语言与决策任务，证明了它相对最先进基线的有效性，同时带来了更好的可解释性与可信度。具体而言，在问答（HotpotQA）与事实核查（Fever）任务上，ReAct 通过与一个简单的 Wikipedia API 交互，克服了思维链推理中普遍存在的幻觉（hallucination）与错误传播（error propagation）问题，并生成更像人类解题过程、比无推理基线更可解释的轨迹。此外，在两个交互式决策基准（ALFWorld 与 WebShop）上，ReAct 仅用一到两个上下文示例（in-context examples）提示，就分别以 34% 和 10% 的绝对成功率优势超越了模仿学习（imitation learning）与强化学习（reinforcement learning）方法。

### 1 引言（Introduction）

人类智能的一个独特之处，是能把面向任务的动作与言语推理（verbal reasoning，或称"内部言语 inner speech"）无缝结合，这在认知科学中被认为对自我调节、策略制定与工作记忆（working memory）的维持有重要作用。以做菜为例：在两个动作之间，人会用语词推理来跟踪进度（"料都切好了，该烧水了"）、处理异常或调整计划（"没有盐，就用酱油和胡椒代替"）、意识到需要外部信息（"面团怎么和？上网搜一下"）；反过来，人也会通过行动（翻菜谱、开冰箱检查食材）来支撑推理。

在 LLM 时代，这两条线索此前各自发展。一方面，思维链（CoT） prompting 能让 LLM 进行多步推理，但这种推理是一个"静态黑箱"：模型只依赖自身内部表示生成思考，不与外部世界接地（grounded），难以做出反应式推理或更新知识，容易产生事实幻觉并在推理链上传播错误。另一方面，SayCan 等工作用预训练语言模型在交互环境中做规划与行动，但通常只把多模态观测转成文本、由语言模型生成领域动作，再用控制器执行，并没有用语言模型对高层目标进行抽象推理或维护工作记忆来支撑行动（Inner Monologue 除外，但它只有受限的言语推理形式）。作者由此提出 ReAct——一个在 LLM 中协同推理与行动、用于通用任务求解的范式，并在 HotpotQA、Fever、ALFWorld、WebShop 四个基准上验证其有效性。论文的四点贡献：(1) 提出 ReAct 这一基于提示的推理-行动协同新范式；(2) 跨基准的大量实验，展示少样本 ReAct 优于只推理或只生成动作的先前方法；(3) 系统的消融与分析，理解行动对推理任务、推理对交互任务的重要性；(4) 分析提示设定下 ReAct 的局限，并通过初步微调实验展示随训练数据增长的潜力。

### 2 ReAct：协同推理与行动（Synergizing Reasoning + Acting）

考虑 Agent 与环境交互求解任务的一般设定：在时刻 t，Agent 收到观测 oₜ，依据策略 π(aₜ|cₜ) 执行动作 aₜ，其中 cₜ = (o₁, a₁, …, oₜ₋₁, aₜ₋₁, oₜ) 是上下文。当映射 cₜ → aₜ 高度隐式、需要大量计算时，学出这个策略非常困难：例如只行动的 Agent 无法从轨迹上下文中推理出结束 QA 任务的正确动作；也读不懂"sinkbasin 1 里并没有 peppershaker 1"这一事实，只能不断产生幻觉动作。

ReAct 的核心想法很简单：把 Agent 的动作空间扩充为 **Â = A ∪ L**，其中 L 是语言空间。属于语言空间的动作 ât（称为"思考 thought"或"推理轨迹"）不影响外部环境、不会产生观测反馈，而是通过在当前上下文 cₜ 上推理来组合有用信息，更新上下文以支撑后续的推理或行动。论文主要关注冻结的大语言模型（PaLM-540B）用少样本上下文示例提示的设定：每个示例是一条人类编写的、包含动作、思考与环境观测的解题轨迹。

思考可以有多种用途：分解任务目标并创建行动计划、注入与任务相关的常识知识、从观测中提取重要部分、跟踪进度并切换子计划、处理异常并调整计划等。对于以推理为主的任务（如 HotpotQA），思考与动作交替密集出现（dense thought）；对于动作数量庞大的决策任务（如 ALFWorld），思考只需稀疏（sparse）地出现在轨迹中最关键的位置，由模型自行决定思考与动作的异步出现。

ReAct 的四大特性：A) **直观且易设计**——标注者只需在动作之上写下自己的思考即可，论文未使用任何特别的格式选择、思考设计或示例挑选技巧；B) **通用且灵活**——适用于问答、事实核查、文字游戏、网页导航等动作空间与推理需求各异的任务；C) **高性能且鲁棒**——仅从一到六个上下文示例学习，就能在不同领域持续超越只推理或只行动的基线；D) **人类对齐且可控**——人类可以方便地检查推理与事实的正确性，还可以通过"思考编辑"在运行中控制或纠正 Agent 行为。

### 3 知识密集型推理任务（Knowledge-Intensive Reasoning Tasks）

#### 3.1 实验设置

**数据集**：(1) HotpotQA——多跳问答基准，需要基于两篇以上 Wikipedia 段落进行推理；(2) FEVER——事实核查基准，每条声明需判定 SUPPORTS / REFUTES / NOT ENOUGH INFO。两者都采用"仅问题（question-only）"设定：模型只收到问题/声明，不提供支撑段落，必须依靠内部知识或与外部环境交互检索知识。

**动作空间**：作者设计了一个简单的 Wikipedia API，仅三类动作：
- `search[entity]`：返回对应实体维基页面的前 5 句；若页面不存在，则返回搜索引擎给出的 top-5 相似实体；
- `lookup[string]`：返回页面中下一句包含该字符串的句子，模拟浏览器 Ctrl+F 功能；
- `finish[answer]`：以答案结束当前任务。

作者强调，这个动作空间显著弱于最先进的词法或神经检索器，目的是模拟人类与 Wikipedia 的交互方式，迫使模型通过显式的语言推理来完成检索。

#### 3.2 方法

**ReAct 提示**：从训练集随机挑选 HotpotQA 6 例、Fever 3 例（作者发现更多示例并不能提升性能），人工编写 ReAct 格式轨迹作为少样本示例。思考覆盖多种用途：分解问题（"我需要搜 x，找 y，再找 z"）、从观测中提取信息、进行常识或算术推理（如 "1844 < 1989"）、引导搜索改写（"也许我可以改搜/查 x"）、综合最终答案（"所以答案是 x"）。

**基线**：通过系统性地删减 ReAct 轨迹构造：(a) **Standard**（标准提示，删去全部思考/动作/观测）；(b) **CoT**（思维链，只保留推理，删去动作与观测）；在其上加 **CoT-SC**（自洽性 self-consistency，温度 0.7 采样 21 条轨迹取多数答案）；(c) **Act**（只行动，删去思考，粗略类似于 WebGPT 与互联网交互的方式）。

**内外部知识结合**：作者观察到 ReAct 的解题过程更事实、更接地，而 CoT 更擅长组织推理结构但容易幻觉。因此提出两种回退（backoff）策略：A) **ReAct→CoT-SC**：ReAct 在给定步数内未得到答案则退回 CoT-SC（HotpotQA 与 FEVER 分别设 7 步与 5 步，因为超过该步数的正确轨迹仅占 0.84% 与 1.33%）；B) **CoT-SC→ReAct**：当 n 个 CoT-SC 样本中多数答案出现次数少于 n/2（说明内部知识不足以自信作答）时退回 ReAct。

**微调（Finetuning）**：由于人工大规模标注推理轨迹困难，作者采用类似 STaR 的自举（bootstrapping）方法，用 ReAct（及各基线）生成的 3,000 条答案正确的轨迹去微调较小的 PaLM-8B/62B，让模型根据输入问题/声明解码完整轨迹。

#### 3.3 结果与观察

**主结果（表 1，PaLM-540B）**：HotpotQA（EM）/ FEVER（Acc）——Standard 28.7 / 57.1；CoT 29.4 / 56.3；CoT-SC 33.4 / 60.4；Act 25.7 / 58.9；ReAct 27.4 / 60.9；CoT-SC→ReAct 34.2 / 64.6；ReAct→CoT-SC 35.1 / 62.0；监督式 SoTA 为 67.5 / 89.5。可见：ReAct 在两个任务上都稳定优于 Act，证明推理对行动（尤其是综合最终答案）的引导价值；ReAct 在 FEVER 上优于 CoT（60.9 vs 56.3），在 HotpotQA 上略逊于 CoT（27.4 vs 29.4）；最好的提示方法都是 ReAct 与 CoT-SC 的组合，且仅用 3-5 个样本即可达到 CoT-SC 采 21 个样本的性能。

**成败模式分析（表 2）**：作者从 ReAct 与 CoT 各随机抽取 50 条对错轨迹（共 200 例）人工标注。成功案例中，ReAct 有 94% 是"推理轨迹与事实均正确"的真阳性，而 CoT 只有 86%（CoT 有 14% 是因幻觉推理或事实而"碰巧"答对的假阳性）；失败案例中，幻觉是 CoT 的主要失败模式（占 56%），而 ReAct 为 0%——ReAct 借助外部知识库，解题轨迹更接地、更可信。但 ReAct 的结构约束也降低了组织推理步骤的灵活性：推理错误占其失败的 47%（CoT 为 16%），其中一个 ReAct 特有的高频错误是模型重复生成先前的思考与动作而无法跳出循环；此外 23% 的失败源于搜索返回空或无用信息，使模型难以恢复并改写思考。

**微调结果（图 3）**：在 PaLM-8B/62B 上，提示式 ReAct 是四种方法中最差的（小模型难以从上下文示例同时学会推理与行动）；但仅用 3,000 条示例微调后，ReAct 反而成为最佳——微调后的 PaLM-8B ReAct 超过所有 PaLM-62B 提示方法，微调后的 PaLM-62B ReAct 超过所有 540B 提示方法。原因在于：微调 Standard/CoT 本质上让模型记忆（可能幻觉的）知识，而微调 ReAct/Act 教会模型"如何（推理并）行动以从 Wikipedia 获取信息"这一更可泛化的技能。

### 4 决策任务（Decision Making Tasks）

**ALFWorld**：与具身基准 ALFRED 对齐的文字游戏，含 6 类任务（Pick、Clean、Heat、Cool、Look、Pick 2），Agent 需通过文字动作在模拟家庭环境中导航交互以完成高层目标（如"把两个钥匙链放进保险箱"）。一个任务实例可包含 50 个以上位置，专家策略需 50 步以上才能解决。每类任务随机标注 3 条轨迹，并用其中 2 条的全部排列组合构造 6 个提示以检验鲁棒性；在 134 个未见过的评测游戏上按任务类型评测。基线 BUTLER 是在每类任务 10⁵ 条专家轨迹上训练的模仿学习 Agent。

结果（表 3，任务特定成功率 %）：最佳 ReAct 试验平均成功率 71%，显著超过最佳 Act（45%）与最佳 BUTLER（37%）；即便最差的 ReAct 试验（48%）也优于后两者的最佳试验；六个对照试验中 ReAct 对 Act 的相对提升从 33% 到 90%，平均 62%。定性观察发现没有思考的 Act 无法把目标正确分解为子目标，或丢失对环境当前状态的跟踪。

**WebShop**：包含 1.18M 真实商品与 12k 人类指令的在线购物网站环境，Agent 需根据用户指令（如"找一个带抽屉、镍色饰面、140 美元以下的床头柜"）通过搜索、选商品、选选项、购买等网页交互完成购买，在 500 条测试指令上以平均得分（Score）与成功率（SR）评估。结果（表 4）：Act 62.3 / 30.1；ReAct 66.6 / 40.0；IL（1,012 条人工轨迹训练的模仿学习）59.9 / 29.1；IL+RL（再加 10,587 条训练指令的强化学习）62.4 / 28.7；人类专家 82.1 / 59.6。单样本 Act 已与 IL/IL+RL 相当，加入稀疏推理后 ReAct 将此前最佳成功率绝对提升 10%。作者注意到 ReAct 更善于通过推理弥合嘈杂观测与动作之间的差距，但所有方法仍远低于会做更多商品探索与查询改写的人类专家。

**内部推理 vs 外部反馈（ReAct-IM 消融）**：与最接近的先前工作 Inner Monologue（IM）对比，IM 的"内心独白"只限于环境状态观测与目标完成情况复述。作者构造了 IM 风格的消融提示 ReAct-IM：ReAct 以 71% 对 53% 的总成功率大幅胜出，在六类任务中的五类保持优势。ReAct-IM 常因缺少高层目标分解而判断错子目标是否完成、下一个子目标是什么，也因缺乏常识推理而找不到物品的可能位置。

### 5 相关工作（Related Work）

- **LLM 推理**：CoT 及其后续（least-to-most prompting、zero-shot-CoT、自洽性、Selection-Inference、STaR、Faithful Reasoning、Scratchpad 等）。与这些"孤立、固定"的推理不同，ReAct 把模型动作及其观测整合进连贯的输入流，使推理更准确并能处理推理之外的任务（如交互式决策）。
- **LLM 决策**：WebGPT 用 LM 与浏览器交互回答 ELI5 问题，但依赖昂贵的人类反馈强化学习；BlenderBot、Sparrow、SimpleTOD 等在对话中决定 API 调用，同样不显式建模推理且依赖昂贵数据。ReAct 只需用语言描述推理过程，学策略的方式便宜得多。SayCan 用 LLM 直接预测机器人动作再由 affordance 模型重排；Inner Monologue 是 ReAct 之前最接近的闭环系统，但其"内心独白"并非真正的内在思考。作者也指出，语言作为一种基础认知机制，将在交互与决策中扮演关键角色。

### 6 结论（Conclusion）

ReAct 是一个简单而有效的、在 LLM 中协同推理与行动的方法，在多跳问答、事实核查与交互式决策任务上取得更优性能并留下可解释的决策轨迹。其局限在于：动作空间庞大的复杂任务需要更多示范才能学好，而这些示范容易超出上下文学习的输入长度限制；在 HotpotQA 上的初步微调实验已显示潜力，但更多高质量人工标注将是进一步提升的关键。未来可将 ReAct 扩展到多任务训练，并与强化学习等互补范式结合，构建更强的 Agent。

### 附录亮点

- **A.1 GPT-3 实验**：text-davinci-002（贪心解码）上 ReAct 在 HotpotQA（500 验证子集）达 30.8 EM、ALFWorld 达 78.4% 成功率，均高于 PaLM-540B 的 29.4 与 70.9，说明 ReAct 提示跨模型有效。
- **A.2 获取最新知识**：对一条标签已过时的 HotpotQA 问题（询问酒店规模，该数字自数据集构建后已增长），Standard 与 CoT 因依赖过时内部知识答错，Act 虽能联网却因缺乏推理引导而失败，只有 ReAct 通过真实网络交互加推理检索到最新信息（酒店现有 2,884 间客房与 220 间套房）并据此作答。
- **A.3 人在回路的行为纠正**：人类只需删除一条幻觉思考并在另一处添加提示（编辑两条思考），就能让原本失败的 ReAct 轨迹成功完成任务——这种"即时策略编辑"是 Act 与此前 RL 方法难以做到的，也超越了对话式目标更新，为人类对齐提供了新的人机协作形式。

## 要点速览

- ReAct 将 Agent 动作空间扩充为 A ∪ L（语言空间），"思考"是影响上下文但不影响环境的特殊动作，由此实现推理与行动的交错生成。
- 思考的五种典型用途：分解目标并制定计划、注入常识、从观测提取信息、跟踪进度、处理异常与调整计划；推理任务用密集思考，决策任务用稀疏思考。
- 知识任务的动作空间只有 search / lookup / finish 三个 Wikipedia API 动作，刻意弱于成熟检索器，以迫使模型显式推理。
- HotpotQA/FEVER 上 ReAct 全面优于 Act（27.4/60.9 vs 25.7/58.9），FEVER 上超 CoT；最佳提示方法是 ReAct 与 CoT-SC 的互补回退组合（最高 35.1 EM / 64.6 Acc）。
- 人工分析 200 条轨迹：CoT 失败的 56% 源于幻觉，ReAct 为 0%；但 ReAct 推理错误更多（47% vs 16%），含重复循环这一特有失败模式。
- 仅用 3,000 条自举轨迹微调后，PaLM-62B ReAct 即超过全部 540B 提示方法——"学会如何获取信息"比"记忆事实"更可泛化。
- ALFWorld 上最好 ReAct 达 71% 成功率，超最佳 Act（45%）与模仿学习 BUTLER（37%），仅用每类 2-3 条示范。
