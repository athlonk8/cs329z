从计算机使用中构建通用用户模型

"Creating General User Models from Computer Use"

"Omar Shaikh et al." · "UIST 2025 · Stanford University & Microsoft Research"

必读论文精读查看原文(PDF) ↗

导读

本文是 CS 329Z 第 11 周"主动式智能体"专题的核心论文。前几周讨论的 Agent 大多在"用户明确发起任务后"才介入,而真正的主动式智能体必须在用户开口之前就理解其处境、预见其需求。要做到这一点,智能体需要的不只是好的推理能力,更是对用户的深度理解——这正是本文要解决的问题。

作者团队(Stanford 的 Omar Shaikh、Michael Bernstein、Diyi Yang 等人与微软研究院的 Eric Horvitz)提出通用用户模型(General User Model, GUM):一种从任意非结构化观察(屏幕截图、文件、通知流)中持续学习用户行为、知识、信念与偏好的计算架构。GUM 的核心表示是带置信度与衰减分数的自然语言命题,围绕 Propose(提出)、Retrieve(检索)、Revise(修订)、Audit(隐私审计)四个模块构建。在应用层面,论文展示了 GUM 如何为 LLM 对话补全上下文、为操作系统过滤通知,并实现了一个能自主发现并执行建议的主动式助手 Gumbo。评价包括 18 人邮件场景的准确率与校准测试,以及 5 人、5 天的真实屏幕使用部署。这篇论文把 HCI 领域数十年的"了解用户的机器"愿景,落到了一个可运行、可评价的系统架构上,是理解"智能体如何获得用户上下文"的必读材料。

论文精读

摘要

人机交互领域很早就想象过真正"理解我们"的技术——理解我们的偏好与习惯,理解我们日常行为的时机与目的。然而,当今的用户模型仍然是碎片化的:它们只为特定应用定制,无法进行跨情境的灵活推理,因而难以实现这些愿景。本文提出一种通用用户模型(General User Model, GUM)架构,通过观察用户与计算机的任何交互来学习用户。GUM 以任意非结构化观察(如设备截图)为输入,构建带置信度加权的自然语言命题,刻画用户的行为、知识、信念与偏好。GUM 可以从与朋友的消息往来中推断出用户正在准备参加一场婚礼;也可以通过观察到多次停滞的编辑和转向阅读相关工作,识别出用户正被合作者的论文修改意见卡住。GUM 引入的架构能从多模态观察中推断关于用户的新命题、检索相关命题作为上下文,并持续修订已有命题。为了展示 GUM 所启用的应用广度,作者演示了如何用它为聊天式助手补充上下文理解、管理操作系统通知使其只在需要时呈现重要信息,以及让交互式智能体跨应用适应用户偏好。论文还实例化了一类新的主动式助手(Gumbo),基于用户的 GUM 代表用户发现并执行有用的建议。评估表明:GUM 对用户做出的推断是校准良好且准确的;基于 GUM 的助手能主动识别并执行具有实际价值、用户自己都想不到要明确请求的操作。总而言之,GUM 利用大型多模态模型理解非结构化用户上下文,既延续了 HCI 的长期愿景,也开启了能预判用户需求的全新交互系统。

1 Introduction(引言)

HCI 的经典愿景都建立在系统对用户目标、任务与情境的丰富理解之上:Weiser 笔下知道主人何时醒来并主动提供咖啡的闹钟、Apple Knowledge Navigator 在用户专注时拦截无关来电。但今天这些愿景仍遥不可及:现有用户模型太窄——只理解音乐偏好、单应用内的工具使用或下一部想看的剧;即使整合跨应用数据,整合也停留在表层,无法在新情境中推理。

本文提出通用用户模型:跨领域、跨时间尺度将用户信息与推断"实体化"的计算模型。用户输入非结构化观察(如屏幕录制),经由基于大型多模态模型(VLM)的推断架构,构建私有的、关于自身行为/知识/信念/偏好的计算表示。架构包含 Propose(观察→带置信度命题)、Retrieve(建索引、按查询返回相关子集)、Revise(新观察到来时重新评估精炼)三个模块,外加基于情境完整性(contextual integrity)理论的 Audit 模块——用 GUM 本身过滤用户不希望被记录的信息;所有数据保存在用户设备上。操作系统、应用或用户本人都可以实时查询 GUM:为 LLM 提问自动附加上下文、会议期间只呈现真正相关的通知、邮件客户端按观察到的优先级排序。

主动式系统层面,论文介绍 Gumbo:持续、私密截屏学习 GUM 的助手,利用 GUM 发现"什么"建议有用并决定"是否、何时"介入执行。对第一作者,Gumbo 观察到婚礼邀请后主动找到了顾及预算的租西装地点;评估中它为参与者生成了研究大纲、跨国搬家计划并整理了邮件——全部仅凭观察主动完成。

技术评估:邮件场景下 18 名参与者判定 GUM 命题总体准确且校准——高置信命题(confidence = 10)100% 准确、全部命题平均 76.15%,消融表明各组件缺一不可;5 人部署 Gumbo 5 天复现了结果,2 人希望继续使用;评估也揭示了隐私与"过于直白命题"等边界条件。

2 Related Work(相关工作)

第一条主线是共同基础(common ground):人与人共享的知识、信念与假设是高效沟通的前提,而 AI 系统与用户几乎没有共享上下文,只能给出过度提供信息、过度自信、无法处理歧义的一刀切回答。弥合鸿沟的既有方案——澄清式问题、记忆对话历史、长上下文、RAG 与 OmniQuery——上下文都仅限于"用户与该模型自己的交互"或预定义来源。GUM 主张:只在用户与模型交互时才建立共识是受限范式,应通过观察主动构建共同基础。第二条主线是有效提示 LLM 很难:ChainForge、EvalGen 等系统帮助用户指定约束,但建立共享上下文的责任仍在用户;混合主动界面、LifeBrowser、PICAN、GPTCoach 等虽用情境寻找介入时机,却被钉死在固定输入结构或传感器上。GUM 拥抱 LLM 擅长的"无约束输入",把自己设计成多模态的"接地引擎"(grounding engine)。

3 General User Models(通用用户模型)

GUM 的核心是完全从观察中学到的、自然语言的、带置信度加权的命题集合。例如作者撰写本章时其 GUM 生成的命题:"Omar 正在写通用用户模型这一节"(置信 0.8)、"正在查看并处理导师的批注"(0.7)、"在技术评估上遇到困难"(0.5)——全部由屏幕截图序列生成。GUM 接受底层大模型能接受的任何输入(VLM 场景下即图像与文本),不强制规定命题类型或结构,命题只受自然语言约束并随输入不断修订。

3.1 命题与置信度:表示 GUM 的抽象

设计借鉴人际交互的共识理论:共识的一个子集可由共享假设定义,人-AI 共识的难点在于识别模型能对用户做出的有效假设。贝叶斯式共识模型把共享知识表示为概率分布而非确定命题集合;GUM 借助大模型上下文学习(可松散理解为贝叶斯更新)实例化这种概率化模型,通过三个抽象:

  • 观察(Observations):GUM 处理的原始输入,只要能被 token 化并输入大模型即可(截图、文件系统、通知流等),每条带元数据(来源、时间戳、唯一标识)。观察是事实记录而非推断。
  • 命题(Propositions):GUM 通过观察构建的文本假设。看到朋友的婚礼邀请会产生表层推断"用户被邀请参加朋友的婚礼"(几乎无需猜测,高置信 1.0);而"用户需要为婚礼购买或租赁西装"是未被明说的复杂推断(低置信 0.4),不确定性纳入因此至关重要。
  • 置信度(Confidences):反映模型对命题为真的确定程度,取决于证据的质量与数量,使应用能在不确定性下决策。

此外,命题带有面向下游应用的元数据。受认知智能体架构启发,每个命题有生成的衰减分数(0-1)表征过时速率:"作者是博士生"衰减缓慢(1.0),"作者正在调试内存泄漏"转瞬即逝(0.6);还有接地(grounding)(支持该推断的观察)与解释命题如何构建的推理(reasoning)。

3.2 与 GUM 交互的接口

GUM 以 Python 包形式实现,可 pip 安装。实例化:需要指令跟随型(V)LM(如 GPT、Claude、Llama);论文用运行在安全服务器上的 Llama 3.3 70B,任何兼容 OpenAI ChatCompletions API 的模型均可;所有命题存在私有的 GUM._propositions 变量中,仅用户可访问。订阅观察:经用户许可,GUM 提供若干钩子(Observers)监听屏幕内容、通知与手动输入,例如用户保存文件时 Filesystem Observer 就把新观察传给 GUM 转换为命题。查询:用户与应用都能用自然语言查询命题及其底层观察,支持控制相关性-多样性平衡(0=最大化相关性,1=最大化多样性)、时间回溯起点、是否按时间戳施加衰减。

4 Applications of General User Models(GUM 的应用)

4.1 提示模型

提示的根本问题是与模型缺乏共享接地:LLM 不知道你在做什么项目、与谁合作、为什么重要,用户被迫把丰富情境压缩成去情境化的查询——输入"help me with this section",前沿 LLM 只能反问"你指的是哪一节?"。GUM 通过查询相关命题弥合鸿沟:返回作者正在修改的章节、此前读过的 Weiser《宁静计算》、导师提到 Interface Agents 等命题,LLM 随即生成高度个性化的回复(如建议强调系统如何通过情境感知扩展宁静计算原则)。

4.2 任何应用都可以查询 GUM

GUM 可成为跨应用的统一情境层,论文用它重访三个经典 HCI 愿景:

  • 宁静技术(Calm Technology,Weiser and Brown):以往需为每个应用定制传感器与 ML 流水线,GUM 无需仪器化即可实现同类应用。第一作者忙于写作时错过了 CHI 早鸟注册——默认系统对每封邮件都发通知导致他全部忽略;直接提示 Llama 3.3"过滤出对我重要的通知"会放行全部,而附带 GUM 命题("有重大截止日期临近""经常忽略账单通知")的同一提示只放行 CHI 注册通知。
  • 界面智能体(Interface Agents,Maes and Kozierok):界面智能体旨在预判需求并自动执行,过去需为每个智能体准备专门数据集与学习目标;GUM 同时提供用户模型与演化偏好。直接问 Llama 3.3 70B"现在适合看电影吗",它会同意并推荐一批无关电影;GUM 增强后知道"草稿还有大量未解决批注""距截止只剩几小时"从而拒绝;把截止日期相关命题全部消融后,同一模型又会正确地同意。
  • 情境感知计算(Context-Aware Computing):以往情境工具包依赖专用传感器,每支持一种新传感器都要手工搭流水线。GUM 可嵌入任何输入:作者把健身日志与 Apple Health 步数导出为文本直接喂入 GUM,零预处理即得到命题"Omar 正把论文截止日期置于日常锻炼之上"(置信度 0.6)。

5 Constructing a General User Model(构建通用用户模型)

工程原则是主要依赖开源模型:GUM 应归用户所有并最终在本地设备运行,避免把私有数据发给第三方。论文使用两个模型:观察屏幕交互用 Qwen 2.5 VL(72B),提出/修订命题用 Llama 3.3 70B。

5.1 观察交互

以往用户模型依赖狭窄的手工记录,现代 VLM 使截图、文件、开放式文本流等非结构化输入成为可能。Observers 设计为通用组件(如音频 Observer 可转写语音返回文本)。论文在 macOS 上实现了 Screen Observer(监听键盘/鼠标 I/O,输入时截屏,用 Qwen 2.5 VL 72B 把截图转成文本更新并生成动作描述,覆盖至多 10 帧)与 Notification Observer(监视系统通知数据库)。

5.2 审计观察(Audit)

即使模型可本地部署,用户也可能意外暴露隐私。Audit 模块在监听更新到达命题集合之前过滤,做法是用 GUM 自己学习用户的隐私期望——用户特定的情境完整性模型(情境完整性理论主张:信息流符合社会情境规范时隐私得以保持,关注"恰当共享"而非二值管控)。例:教授的 GUM 观察过其与同事讨论课程、分享论文,但从未见其共享登录凭证;当其在金融网站输入银行密码时,Audit 检索过往命题("对共享访问凭证很谨慎""只在配偶间讨论财务"),生成对情境完整性五问的回答(是否披露新信息、数据类型、主体、接收者、是否应传输),判定拦截。

5.3 构建命题(Propose)

Propose 把观察转换为命题并生成推理轨迹与置信度。推理并生成命题:先生成解释观察与用户关系的 rationale(如"用户似乎分心了,在冰淇淋配方视频与 LaTeX 窗口间交替"),再把观察与 rationale 一起输入生成命题("用户写作时周期性地看冰淇淋配方");rationale 既给用户解释也普遍提升表现。生成置信度:logits 原生预测过度自信,直接提示模型在 1-10 尺度打分再归一化到 0-1 更校准。命题级衰减:不同命题随时间的衰减速度不同("正在吃冰淇淋"快于"是博士生"),由 LLM 把命题全部信息放入上下文生成 1-10 的专属衰减分。

5.4 检索情境敏感的命题(Retrieve)

需要把新命题与 GUM 已知内容比较,速度至关重要(每条观察产生多条命题、需成百次查询)。采用两阶段"检索+重排":先 BM25 检索,再 LLM 重排。新近度调整:命题带衰减分 α_i,定义 γi = exp(−αi·k·age(di))(k=2,age 以天计),调整后相关性 r̃_i = r_i·γi。多样性:用最大边际相关性(MMR)平衡相关性与多样性(TF-IDF 余弦相似度,MMR = λ·r̃_i − (1−λ)·δ_i,λ=0.5)。重排与过滤:LLM 重排器把检索命题分为 identical / similar / unrelated;连续 identical 即触发修订。

5.5 修订命题(Revise)

被标记为 similar 的新命题可能与旧命题矛盾或印证,Revision 模块把新旧命题及其全部元数据编码进同一提示,可一次修订多条:重写命题、重新生成置信度并更新元数据。示例:旧"用户写作时周期性看冰淇淋配方"(置信 6,衰减 4)+ 新"用户在会议中给同事发冰淇淋配方"(置信 6,衰减 2)→ 修订为"用户经常被冰淇淋配方分心"(置信 10,衰减 1);矛盾命题相遇时置信度也可能下调。被修订到零置信的命题为透明起见保留,但默认查询不返回。

6 评估 GUM:准确率与校准

选择邮件作为受控评估场景:收件箱跨模态地包含多样且相关的信息,又充斥无关内容,"邮件过载"使综合重要信息变得困难,GUM 必须在此挑战下保持准确;同时邮件的受控、语义丰富性质也便于标注。

消融条件:生成准确命题很容易(可以只产出"用户在用电脑"这类无聊事实),因此评估相对质量:(1) No {Retrieve, Revise}:只创建命题、无置信度,无法检索过往上下文;(2) No {Retrieve}:启用修订,但用滑动窗口代替完整检索引擎;(3) Full:完整架构。

流程:18 名参与者(滚雪球+口碑招募;年龄中位数 26,8 男 10 女;39% 白人、50% 亚裔)导出最近 200 封邮件,按收件箱顺序逐封喂入训练自己的 GUM;每人评估 30 条按时间与置信度分层抽样的命题(每条件 10 条),做二元准确性判断与成对排序(允许平局),最后完成开放式调查。基础设施仅用开源模型:Llama 3.3(70B)量化版运行在 80GB NVIDIA H100 上,用 Skypilot 自动扩缩容。

评估方法:准确性用均值与 t 检验;相对排序转成成对胜率并用 Holm 校正的二项检验;校准用 Brier 分数(预测概率与结果的均方差,越低越好),1-10 置信度先归一化到 [0,1]。

结果:

  • 完整架构优于消融:胜率(均值,95% 置信)Full = 0.618±0.07,No {Retrieve} = 0.463±0.07,No {Retrieve, Revise} = 0.420±0.07,Holm 校正检验显著(p<0.05)。两个消融之间无显著差异——相关邮件往往在时间上相隔很远,没有检索的修订(滑动窗口)捕捉不到长程依赖,"没有检索,修订彻底失效"。
  • 命题既校准又准确:置信度 >0.8 的命题被判正确的比例是 88.2%;置信度 =1.0 时为 100%;全部命题(不论置信)平均正确率 76.15±5.85。参与者对总体准确度评分平均 6.47(1-7 Likert)。Brier 分数 0.17±0.03,几乎所有校准误差来自欠自信——作者认为这优于过自信:过自信的用户模型可能错误假定它了解用户偏好,欠自信则让 GUM 更谨慎地适应。单独看准确性,各条件差异不显著(Full 76.15±5.85,No {Retrieve} 73.28±4.42、Brier 0.36±0.07,No {Retrieve, Revise} 74.41±7.81),差距体现在校准与偏好排序上。
  • "写在纸上感觉有点怪":GUM 命题相当直白,如从一连串外卖邮件推断参与者"重视便利并愿意为此付费"、对另一参与者正确推断"可能不总有时间立即读完所有邮件";这类 uncomfortably accurate 的洞察往往置信度较低。
  • 邮件只是真实用户情境的一维代理:有参与者反馈"这个账户收到的邮件不代表我的生活"。错误常源于 GUM 过度聚焦参与者生活的某个侧面(财务、某个爱好或近期购物),这推动了 §8 的屏幕级端到端评估。

7 评估 GUM:隐私审计模块

Audit 模块让 GUM 用自己对用户的理解推断情境化隐私偏好。评估沿用 §6 的 18 名邮件参与者:跳过(即标记)任何违反个人隐私偏好的命题,并对 GUM 的情境完整性回答做 1-7 Likert 评分与最佳版本选择。

结果:完整 GUM 被标注的 180 条命题中只有 7 条被标记违规;情境完整性生成的认同度平均 6.06/7;61.1% 的参与者认为完整 GUM 的回答最好(无检索 22.2%、无修订 16.6%);sanity check 确认没有命题逐字包含信用卡号、电话号码或地址。但仍有 7 条观察绕过了 Audit:有参与者惊讶于 GUM 能从邮件中点名具体朋友;另一参与者发现命题基于钓鱼邮件而非真实兴趣、却带不低的置信度——广告与垃圾邮件可以恶意改写 GUM。GUM 的输入面比一般 VLM 更大,提示注入风险随之放大;作者认为可像红队测试那样缓解(但无法完全消除)此类 GUM 注入攻击。

8 评估 GUM:通过 Gumbo 的端到端研究

最终评估以形成性研究部署 Gumbo,分 burn-in(安装配置、静默学习)与 active use 两阶段,流程经 IRB 批准(上限 5 人);基础设施同 §6,另部署 Qwen 2.5 VL 72B 做屏幕转写。参与者经滚雪球与口碑招募(使用此类系统需要高度信任,均为作者熟人或熟人的熟人),同步入组/出组约一小时,报酬 75 美元;5 人均在美国、18 岁以上(2 白人、2 亚裔、1 非裔,均有本科学历),覆盖工作与个人用途(HCI 研究生 P1/P2、土木工程研究生 P3、数据科学家 P4、NLP 研究生 P5)。burn-in 持续 24 小时(收集数据但不显示建议,解决冷启动),active use 四天;出组时收集建议标注与反馈并做半结构化访谈,分析先复算准确率与校准,再做两轮开放式编码。

结果:

  • GUM 端到端依旧准确且校准:抽样命题准确率 0.79±0.07,Brier = 0.28±0.04,误差同样来自欠自信。事实型命题("P1 在做健康与行为干预研究")几乎无需犹豫就被标对且置信度更高——"这有什么特别的?这就是我。"(P4)
  • 也许过于准确……:对价值观、能力、规范下判断的命题("P2 可能因大量未读邮件与通知感到压力""P4 对工作不满意",均被标为正确)引发复杂反应:P4、P5 觉得有趣,P1 觉得被评判,P2 感到被看见,P3 则表示"(关于能力的命题)就算是真我也会隐藏,只给我看建议"。
  • Gumbo 为所有参与者提供了强到优秀的建议:7 分 Likert 上 25% 的建议被评为强(6)或优秀(7);P2、P3 希望研究结束后继续运行。高分建议往往深度使用了底层 GUM——P1 的搬家建议:"它知道我室友是谁、我们的预算、要搬去哪、我担心这次搬家。它从入住日期倒推、排了时间表、找好了搬家公司。而我跟室友一半对话都不是用英语进行的。"有用建议分两类:当下即时帮助(如 Gmail 开通知的分步指南)与"我根本没想到"的机会(如识别出 P3"用 Overleaf 建新想法骨架"的习惯并直接生成 LaTeX 大纲;根据 P5 看 Twitch 的暂停回放位置推荐玩同一角色的主播)。
  • 情境化能动性:参与者关心能控制哪些情境的观察被转化为命题(P3 建议对低置信命题先向用户确认);Gumbo 也尊重用户偏好——P4 喜欢亲自做旅行规划,Gumbo 于是只给蜜月行程的调整想法而不代做整个计划。
  • 错误与边界:隐私是首要关切("如果我不认识你、不信任你,我绝不会装这个东西。"——P4);有人逐渐忘记 Gumbo 在处理数据,有人全程警觉("它一直在理解我和我的工作,这其实有点可怕。"——P3)。执行能力是现实限制:20.69% 的建议"方向对但执行失败"(如声称已设置提醒,实际没有通知 API 权限)。LLM"热心过头"导致抢跑或建议用户已完成的事。P1 指出对敏感主题的推断标准应当严格强于上下文的暗示、且 Audit 模块自身应可审计。所有参与者都意识到屏幕之外的生活无法被捕捉,以及隐私-能力的此消彼长。

9 Discussion(讨论)

9.1 反思命题:作者从未把 Gumbo 设计成自我反思工具,但参与者深度参与了命题内容。部分命题过于坦率、直接构造价值判断——这可能是提示的副作用(GUM 被要求做准确真实的评估),而诚实评估确实有利于下游建议;但准确的 GUM 也可能纵容用户沉迷于"自认为有益"的行为。"理想自我 vs 真实自我"的落差是经典心理学现象;由此引出设计问题:Gumbo 应提供原始用户模型、净化版本,还是隐藏命题?一种方案是按情境自适应呈现。

9.2 隐私悖论:人们口头上在乎隐私,却会为利益实际让渡隐私。GUM 看得越多就越精准,部分参与者最初聚焦隐私风险,最终却主动提供更多数据——两人想在研究后继续使用。如果向私有本地 GUM 共享数据是安全且值得的,披露就会自我强化;但若考虑意外披露或安全风险,这个回路可能反噬。

9.3 伦理与社会风险:(1) 说服、广告与监视——作者强烈建议 GUM 只在终端用户电脑或个人基础设施上训练与托管(全文指导原则:全部开源模型、自管基础设施),外部访问必须受控且可审计,并警惕第三方未经同意在应用内训练用户的 GUM。(2) 操纵 GUM——垃圾邮件已被证明可恶意改写 GUM 的底层命题;攻击者可以不针对用户而构造消息操纵 GUM,进而影响所有依赖它的应用,可考虑对"出格"输入向用户确认或开发 GUM 版垃圾过滤。(3) 偏见——GUM 构建在有偏见的模型之上,实际上扩大了推荐系统的表面积,部署前需对抗性红队测试。

9.4 局限与未来工作:抽样偏差——端到端评估依赖信任、滚雪球抽样且仅 5 人,结果最可信的泛化范围是熟悉 AI 的技术用户;幻觉与错误归因——仍有少数既自信又错误的命题;屏幕仍是情境的窄代理。作者也指出多个会被未来进展消解的设计约束:检索之所以必要,是因为模型无法可靠处理超长上下文;显式置信度言语化之所以必要,是因为 logits 未校准。未来模型上下文更长、更小、可完全端侧运行(当前 GUM 每天保存约 1GB 截图、转写后仅 5MB),并可超越视觉与语言两种模态。

10 Conclusion(结论)

GUM 通过观察日常行为学习丰富的用户情境表示:把非结构化交互转换为带置信度的命题,并随证据积累持续精炼。它既能接地语言模型,也支持代表用户行动的主动式系统(Gumbo)。评估表明 GUM 能产出快速、校准且准确的推断;作者认为 GUM 提供了一个框架,推动我们走出各自为政的应用级用户模型,走向在人生众多情境中都理解"你是谁"的通用用户模型。

要点速览

  • 核心主张:现有用户模型"太窄"(单应用、表层整合),应代之以跨领域、跨时间尺度的通用用户模型(GUM),从任意非结构化观察中学习用户的行为、知识、信念与偏好。
  • 表示:GUM = 带置信度(0-1)的自然语言命题集合,辅以衰减分数(命题过时速率)、接地(支持观察)与推理轨迹三类元数据;不对命题类型施加结构约束。
  • 四模块架构:Propose(观察→推理→命题+置信度+衰减)、Retrieve(BM25 检索 + 新近度衰减 γi = exp(−αi·k·age) + MMR 多样性 λ=0.5 + LLM 重排 identical/similar/unrelated)、Revise(新旧命题合并改写、重生成置信度;零置信命题保留但不返回)、Audit(用 GUM 自身实例化情境完整性理论,五问判定是否拦截观察)。
  • 隐私优先工程:全开源模型(Qwen 2.5 VL 72B 转写屏幕、Llama 3.3 70B 生成/修订命题)、数据留在设备/自有服务器、私有命题变量仅用户可访问、工具默认关闭。
  • 应用谱系:为欠规格提示补全上下文(grounding gap)、操作系统通知过滤(只放行 CHI 注册通知的例子)、界面智能体复兴(GUM 消融实验证明"不适合现在看电影"的判断来自用户模型)、任何应用通过统一接口查询 GUM。
  • Gumbo 主动式助手:每条新命题生成 5 条候选建议;用 GUM 估计 P(τ|G)、收益 B、误报/漏报代价 C_FP/C_FN,按期望效用不等式决定是否打断,并用令牌桶限速每分钟 1 条;能自己执行就执行(沙盒、避免不可逆副作用),反馈作为普通观察回灌。
  • 关键数字(邮件评估,N=18):全部命题平均准确率 76.15±5.85,置信度>0.8 时 88.2%,置信度=1.0 时 100%;Brier 0.17±0.03(误差主要来自欠自信);排序胜率 Full 0.618±0.07 显著高于两个消融(0.463/0.420,p<0.05);无检索时修订失效。
  • 隐私审计结果:180 条命题仅 7 条被标记违规,情境完整性回答认同度 6.06/7,61.1% 参与者选完整 GUM 最佳;但垃圾/钓鱼邮件可注入改写 GUM,提示攻击面问题。
  • 端到端部署(N=5,5 天):命题准确率 0.79±0.07、Brier 0.28±0.04;25% 建议被评为强/优秀;20.69% 建议方向正确但执行失败;两人要求继续使用;屏幕数据约 1GB/天(转写后 5MB)。
  • 开放问题:过于直白的命题(理想自我 vs 真实自我)、隐私悖论(越用越愿意喂私有数据)、GUM 操纵与提示注入、偏见放大、屏幕之外的生活盲区——这些边界条件正是后续工作(包括下一篇 Next Action Predictors)的起点。
